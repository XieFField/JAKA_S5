# JAKA S5 推拿机器人项目架构与阶段交接说明

更新日期：2026-09-08

本文面向新加入项目组的开发成员，用于说明项目目标、代码边界、运行链路、当前验证进度、已知问题和后续工作。本文描述的是当前工程事实，不代表医疗效果或临床安全已经得到验证。

## 1. 项目目标与当前阶段

项目目标是在 JAKA S5 上形成可扩展的推拿机器人控制框架，最终支持：

1. 从业务待机位安全到达工作区域；
2. 根据输入的手法、接触点、表面法向和切向生成任务；
3. 在接触人体前保持按摩头姿态正确，并生成预接触点；
4. 通过六维力传感器识别接触并建立目标法向力；
5. 在维持柔顺接触的同时执行推、按、揉；
6. 释放接触、从患者上方退出并安全回待机；
7. 对规划、执行、力控和恢复过程提供可审计日志与失败门禁。

当前已经完成“轨迹、状态机和执行后端的第一版集成”。Gazebo 已完成三种手法和初步模拟接触闭环；真机已完成自由空间按法、揉法以及 native PTP/LIN/CIRC 的阶段验证。真实人体接触、恒力与手法轨迹的复合控制尚未完成真机验收。

## 2. 两个仓库及版本关系

工程必须使用两个并列 ROS 2 工作区，不要把供应商仓库复制到业务仓库中。

```text
/home/xieffield/jaka_ros2
└── JAKA 官方 ROS 2 仓库的 Fork
    branch: feature/massage-s5-integration
    integration commit: 504362f

/home/xieffield/xieffield/pratice/massage_robot_ws
└── 推拿机器人业务、规划、仿真和适配代码
    branch: main
```

依赖方向固定为：

```text
ROS 2 Humble
    -> jaka_ros2
        -> massage_robot_ws
```

构建和运行前必须按这个顺序 source。反序 source 或混用旧终端，会导致 Action/Service 类型不一致、运行到旧二进制等问题。

## 3. 总体架构

```text
业务请求
  technique + contact pose + surface normal/tangent + execution mode
                              |
                              v
massage_task: MassageTaskStateMachine
  - 业务状态流转
  - 全流程预规划
  - 姿态、连杆高度、肘型和回程安全门禁
  - 接触、力控、取消和失败恢复
                              |
              +---------------+----------------+
              |                                |
              v                                v
massage_motion                        massage_jaka
  MoveIt/Pilz 规划                      JAKA 生命周期与执行适配
  IK 多解搜索                           native PTP/LIN/CIRC 客户端
  PTP/LIN/CIRC 公共语义                 FT/柔顺/工具驱动适配
  推按揉路径生成                        错误码与控制权互斥
              |                                |
              +---------------+----------------+
                              |
                +-------------+-------------+
                |                           |
                v                           v
          Gazebo/ros2_control        jaka_driver + JAKA SDK
```

规划与执行是分离的：MoveIt/Pilz 负责得到满足碰撞和几何约束的路径；执行器根据环境和运动类型选择 Gazebo 控制器或 JAKA 原生接口。不能因为使用原生 SDK 就跳过 MoveIt 的规划与安全门禁。

## 4. 包职责

### 4.1 `massage_description`

- JAKA S5、按摩头、六维力传感器和世界坐标系的 Xacro/URDF；
- 仿真和真机共享机器人描述；
- 业务 TCP 统一为 `massage_tool_tip`；
- 规划和接触逻辑不得直接把 `Link_06` 法兰当按摩头接触点。

### 4.2 `massage_motion`

- 定义 `MotionType`、`MotionTarget`、规划请求和执行请求等公共语言；
- 封装 Pilz PTP、LIN、CIRC 规划；
- 动态 IK 超时、多 IK 解搜索和候选竞争；
- 生成推、按、揉的几何路径；
- 末端工具轴对齐、轨迹连续性、关节路径等价、连杆高度和肘型几何检查；
- 提供 MoveIt、ros2_control、hybrid executor 和导纳公共接口；
- `native_ptp_contract` 负责证明 MoveIt PTP 与原生 `joint_move` 目标之间的等价关系。

### 4.3 `massage_task`

- `MassageTaskStateMachine` 是业务流程的唯一编排入口；
- 支持 `plan_only`、`free_space`、`compliant_contact` 三种执行模式；
- 在任何真机运动前先规划并检查完整路线；
- 运行时从新鲜实际关节状态重新规划相邻段，避免上一段实际终点误差污染下一段起点；
- 失败或取消后尝试释放力控、抬升退出并回待机，同时保留 primary error；
- 记录完成的接触 session 数和手法 cycle 数。

当前主要状态流为：

```text
Idle
 -> MoveStandby
 -> MoveWorkReady
 -> VerifyToolAlignment
 -> MovePreContact
 -> MoveTechniqueStart
 -> ZeroAndValidateFt
 -> GuardedContactEntry
 -> ContactConfirmed
 -> RampNormalForce
 -> ExecuteTechnique
 -> ReleaseNormalForce
 -> Retreat
 -> ReturnOverhead
 -> MoveSafeReturnExit
 -> Complete
```

`free_space` 会跳过真正的 FT 校零、接触检测和恒力建立，但仍执行同样的空间轨迹与安全回程。它只能证明路径和执行链可行，不能证明推拿接触控制可行。

### 4.4 `massage_jaka`

- 封装登录、上电、使能、错误状态和硬件 readiness；
- `JakaNativeJointExecutor`：把通过等价门禁的 PTP 路由到 `/jaka_driver/execute_joint_move`；
- `JakaNativeCartesianExecutor`：把 LIN/CIRC 路由到 `/jaka_driver/execute_cartesian_move`；
- JAKA 柔顺、力传感器、tool-drive 和错误码适配；
- 真机程序不直接散落调用供应商 SDK，统一通过该层进入驱动。

### 4.5 `massage_bringup`

- 组织 Gazebo、robot_state_publisher、MoveIt、RViz、控制器和任务节点；
- `massage_task_sim.launch.py` 是三种手法的仿真业务入口；
- `real.launch.py` 启动唯一的真机 driver/MoveIt 基础设施；
- `massage_task_real.launch.py` 只启动任务节点，不重复启动 driver；
- 所有真机运动入口默认 `execute=false` 或 `plan_only`，必须显式确认。

### 4.6 `jaka_msgs` 与 `jaka_driver`

项目 Fork 新增或扩展的关键接口：

- `/jaka_driver/execute_joint_move`：非阻塞原生 `joint_move` Action；
- `/jaka_driver/execute_cartesian_move`：原生 LIN/CIRC Action；
- `/jaka_driver/get_rapid_rate`、`set_rapid_rate`；
- `/jaka_driver/get_admittance_state` 和柔顺配置接口；
- `/jaka_driver/set_approach_speed_limit`：独立设置并读回控制器接近速度上限；
- FT 软限位、tool-drive 和生命周期服务。

native motion 与旧 `FollowJointTrajectory/servo_j`、柔顺和 legacy service 使用独占控制权，防止多个入口同时控制机器人。`servo_j` 仍保留用于诊断或以后确有必要的在线控制，但当前生产自由空间流程不再使用它。

## 5. 三种手法的当前业务语义

所有手法首先根据患者表面法向和切向构造按摩姿态。当前水平测试面上要求按摩头工具 Z 轴与世界 `-Z` 对齐，容许误差由 tool-alignment gate 控制。姿态正确后才允许到达工作准备位和预接触位。

### 推法 `push`

- 输入接触起点、世界 XY 平面切向和推行长度；
- 当前测试方向为世界 `+Y`，长度默认 `0.08 m`；
- 每次推行后回到预接触点，再开始下一次；
- 默认重复三次；
- 真实业务最终应在保持目标法向力的同时沿切向推行。

### 按法 `press`

- 沿表面法向进行按下/回弹；
- 默认上下循环三次；
- 循环间保持接触语义，不应把每次回弹设计成完全离开患者；
- 当前真机验收仍是自由空间位置轨迹，不包含真实恒力。

### 揉法 `knead`

- 在保持法向按压力的同时，在世界 XY 切平面执行圆周；
- 默认揉三圈，圆半径和周期可配置；
- 原生执行阶段使用 CIRC 分段表达圆周；
- 当前真机验收仍是自由空间圆弧运动。

## 6. 规划与安全门禁

### 6.1 姿态和 IK

- 目标姿态由表面法向/切向生成，不使用任意固定 RPY 拼接；
- 动态 IK 搜索时间随平移和旋转距离增加；
- 搜索多个唯一 IK 解，每个解再进行运动规划；
- 候选根据路径长度、时长、最大关节行程和安全指标竞争选择；
- 单个 IK 或规划失败只淘汰该候选，不立即终止整个任务。

### 6.2 肘上和连杆几何

- `Link_03` 相对业务待机参考高度的最大下降量目前为 `0.20 m`；
- 该高度阈值只是底线，不等价于“肘上”；
- 肘型还通过肩、肘、腕相关连杆构成的几何关系，计算肘部相对肩腕连线的有符号偏移；
- 规划候选优先选择肘上构型，并检查轨迹全过程，不能只检查终点；
- 末端举得较高等特殊场景需要允许合理退化，但必须保留连杆最低高度和碰撞门禁。

这套几何判定与未来柔顺控制兼容：柔顺阶段只允许在局部接触方向产生有限偏移，不应改变肩肘腕的大尺度构型。运行时仍需持续监控几何裕量，接近阈值时停止切向手法并进入安全退出。

### 6.3 回程

- 结束后先沿患者表面法向抬升；
- 再规划患者上方的安全退出段；
- 最后 PTP 回业务待机位；
- 回程检查按摩头高度、`Link_03` 高度和患者保护区域净空；
- 不允许直接从患者下方或穿过患者区域回待机。

## 7. 真机执行链

当前真机使用混合执行器：

| 运动类型 | 规划 | 真机执行后端 |
| --- | --- | --- |
| PTP | MoveIt/Pilz + IK 候选竞争 | JAKA SDK `joint_move` |
| LIN | MoveIt/Pilz LIN | JAKA SDK `linear_move` |
| CIRC | MoveIt/Pilz CIRC | JAKA SDK `circular_move` |
| 仿真全部类型 | MoveIt/Pilz | ros2_control |

PTP 发送前必须满足：规划起点与新鲜 `/joint_states` 一致、路径接近关节直插、轨迹已经通过碰撞/姿态/肘型/高度门禁。原生 SDK 只接收最终目标和速度参数，不能重现任意 MoveIt 采样路径，因此路径不等价时必须拒绝，不能自动回退到 `servo_j`。

native Action 的结束条件已经改为“机器人状态健康且持续进展”。预计时长只作为诊断参考；只要机器人仍在运动且误差持续下降，就不会因为估算时间到期而 `motion_abort()`。取消、失能、错误码、碰撞、停止后终点未达和长时间无进展仍会失败并停止。

## 9. 当前已知问题与风险

### P0：原生 PTP 明显偏慢

最近工作准备位 PTP 数据：

```text
programmed_speed=0.750 rad/s
rapid_rate=0.400
nominal_effective_speed=0.300 rad/s
actual progress approximately 0.032 rad/s
elapsed approximately 61.2 s
```

LIN 已由现场确认速度正常，因此问题现在限定在 `joint_move`/PTP 链路。接近速度上限从 `10 mm/s, 0.01745 rad/s` 调到 `100 mm/s, 0.5 rad/s` 后，PTP 速度没有变化，不能再把该参数当作 PTP 根因。

下一步应使用单一小位移对照法确认：

1. 固定相同目标、SDK speed 和 acceleration；
2. 只改变 `rapid_rate`，记录真实关节速度；
3. 查询示教器中的关节运动、安全和运行模式限速；
4. 与 JAKA 工程师确认 SDK 2.2.2 `joint_move` 的 speed/acc 语义；
5. 在证据明确前不要继续叠加补偿倍数。

### P0：真实柔顺推拿尚未闭环验收

- 尚未完成真实软体/人体表面的接触搜索；
- 尚未完成恒力 + 切向 LIN/CIRC 的组合验证；
- 推、按、揉真机 PASS 当前均只代表自由空间轨迹；
- 力传感器、机器人碰撞阈值和业务最大力需要分层设计，不能简单全部放大。

### P1：TCP 语义需独立复核

另一路分析曾报告业务 `massage_tool_tip` 与控制器当前 TCP 可能存在固定偏差。该问题与本轮 PTP 慢速无关，但在真实接触前必须通过 FK、TF、示教器工具坐标和小范围 LIN 对照独立确认。

### P1：控制器参数生命周期

- 当前现场曾调整 FT 软限位和接近速度上限；
- 这些参数是否跨控制器重启持久化尚未形成可靠结论；
- 后续启动流程应显式读取、校验并记录参数，而不是依赖上次现场状态；
- 自由空间和接触阶段应使用不同速度上限，切换时必须读回确认。

### P1：真机推法完整验收

推法主要路径已经执行观察过，但历史运行在回待机/段间衔接处出现过最终失败。修复已经进入公共状态机，仍需用当前版本完成一次从待机到三次推行再安全回待机的完整 PASS。

## 10. 后续开发顺序

### 阶段 1：收口自由空间真机链

1. 定位并解决 PTP 低速，只做最少的单变量真机对照；
2. 完成推法当前版本的完整真机 PASS；
3. 独立确认业务 TCP 与控制器工具坐标一致；
4. 固化自由空间速度、加速度、rapid rate 和控制器限速的配置契约。

### 阶段 2：接触与恒力基础

1. 执行 R10 配置只读、plan-only、预接触和软块恒力保持；
2. 建立 FT 校零、异常值、方向、世界系转换和新鲜度门禁；
3. 确认接触搜索速度、接触阈值、目标力斜坡、最大力和退出条件；
4. 在软体模型上完成重复接触与安全恢复。

### 阶段 3：柔顺手法组合

1. 推法：恒定法向力 + 切向直线；
2. 按法：不完全离开表面的周期法向位移/力变化；
3. 揉法：恒定法向力 + 世界 XY 圆周；
4. 对每种手法验证力误差、轨迹误差、姿态误差和停止延迟；
5. 把仿真参数与真机参数分开管理，不直接照搬。

### 阶段 4：业务接口与工程化

1. 将 technique、接触点、表面法向、切向、力度、长度和循环数做成稳定 Action；
2. 增加任务取消、暂停、恢复和操作者确认；
3. 固化日志、CSV、测试报告和版本组合；
4. 增加真实患者前的假体、软块和异常注入测试矩阵。

## 12. 协作约定

- 一个控制柜只能运行一个 `jaka_driver`，不要在多个终端重复启动 real stack；
- 新功能优先进入 `massage_motion` 公共接口或 `massage_task` 状态机，不要把业务逻辑写入 driver；
- 供应商通用能力才修改 `jaka_ros2`，项目专属策略放在 `massage_robot_ws`；
- 不自动上电、使能或运动真机；真机执行由现场操作者完成；
- 日志中的 `PASS` 必须注明层级：规划 PASS、自由空间 PASS、仿真柔顺 PASS 和真机接触 PASS 不能互相替代；
- 修改安全阈值前先保存原值，结束后恢复并读回；
- 任何执行失败都先保存任务日志和 driver 日志，再决定是否重试；
- 不提交 `build/`、`install/`、`log/` 和 `/tmp` 遥测文件。

## 13. 推荐分工

- 运动规划：IK 候选、肘型/高度门禁、安全回程和 PTP 速度问题；
- 力控：FT 标定、世界系变换、R10、恒力与轨迹组合；
- 状态机：业务 Action、取消/恢复、阶段速度和参数切换；
- 仿真测试：患者软体模型、接触参数和异常注入；
- 真机集成：控制器配置、TCP/负载、测试清单、日志与验收报告。

每项工作都应提交“代码 + 可复现命令 + PASS/FAIL 指标 + 未验证边界”，避免只以肉眼看到机器人移动作为完成标准。
